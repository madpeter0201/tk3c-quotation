# 官方商品網址匯入評估

## 結論

可以設計「貼上官方商品網址」的匯入入口，對少量商品建檔很實用；但目前專案是 GitHub Pages 靜態前端，沒有能安全抓取外部網頁的後端。直接從瀏覽器 `fetch()` 官方網站也會受同源政策與 CORS 設定限制，因此現階段不應把「貼網址」做成看似已自動匯入的假功能。[MDN：CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)

建議產品管理員貼入網址後，由受控的後端擷取「待審核草稿」，再人工確認並發佈；不直接覆寫正式目錄。這能節省複製規格的時間，同時保留人員對資料正確性的判斷。

## 建議匯入流程

1. 管理員選擇已核准的品牌來源，貼上 HTTPS 商品頁網址。
2. 系統檢查正式網域白名單、網址格式、重新導向目的地和回應大小，再擷取網頁。
3. 優先讀取頁面中的 `Product` 結構化資料；接著使用該品牌已驗證的頁面解析器。Google 文件列出產品結構化資料可能包含品牌、識別碼、規格與價格等欄位；本專案可擷取官方頁面公開市價，但網站是否提供這些欄位、內容是否與目前頁面一致，仍需逐站驗證。[Google：Product 結構化資料](https://developers.google.com/search/docs/appearance/structured-data/product)
4. 顯示「原始頁面值／擬匯入欄位」比對畫面，逐欄標示來源、擷取時間及信心狀態；規格不清或有衝突的欄位留白，不能猜值。
5. 管理員確認品牌、品名、型號、類別規格和市價後，建立待審核記錄。核准時保留來源網址、擷取時間、價格類型、幣別、地區、對應商品版本、原始欄位快照、審核者和變更紀錄。

第一版匯入品牌、品名、型號、官方型號識別碼、商品規格及官方頁面公開市價。市價需標示是官方建議售價、官方頁面售價或促銷價；若無法判別價格類型、幣別或對應版本，先留待人工確認。這是公開參考價，不等同公司核准的成交價、成本或業務報價。完全不匯入庫存或供貨狀態。運費與圖片授權不屬於本次匯入範圍。

## 可用性與正確性評估

| 欄位 | 預期實用性 | 主要正確性風險 |
| --- | --- | --- |
| 品牌、品名、型號 | 高 | 頁面標題與正式型號命名可能不同；同一商品有不同地區型號 |
| 商品規格 | 中至高 | 官方頁可能缺欄、延遲更新，或規格藏在變體選項／動態載入內容 |
| SKU、GTIN 等識別碼 | 中 | 不是每頁都公開；型號、顏色、容量的識別碼可能不同 |
| 官方公開市價 | 中 | 依地區、時間、商品版本及促銷而變；必須保存價格類型、幣別、版本與擷取時間 |
| 庫存、供貨狀態 | 排除 | 不蒐集、不儲存、不顯示 |
| 商品圖 | 低 | 圖片可讀取不代表可再散佈或用於公司資料庫，需確認授權 |

官方網站是較好的候選來源，但「來自官方網域」不等於欄位完整、資料即時或公司已取得再利用授權。Google 的結構化資料文件也將它定位為網站向搜尋引擎描述產品的標記方式，並未保證其可替企業內部商品主檔背書。

## 安全與維運要求

- 前端只負責輸入網址與呈現草稿；由後端執行抓取，避免依賴各品牌的 CORS 設定。
- 使用已核准的來源網域清單；驗證完整 hostname 與 HTTPS，限制重新導向，拒絕本機／私有網段、非 HTTP(S) 協定、含帳密網址和超大回應。OWASP 建議避免直接接受任意完整 URL，並採用可信目的地白名單，降低 SSRF 風險。[OWASP：SSRF 防護](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- 不帶入管理員 Cookie、登入狀態或內網認證去抓網頁；不執行來源頁面的 JavaScript。
- 保留欄位級來源與修改稽核。規格匯入不得自動覆蓋人工核准值；解析器更版時以差異草稿讓人員複核。
- 遵守品牌網站條款、robots 規則及資料授權；若未取得明確可再利用依據，採人工輸入或品牌提供的正式 API／資料 feed。

## 試辦建議

先挑一個品牌和一個商品類別，使用已獲授權的少量頁面做離線試辦。建議驗收目標：品牌／型號識別零誤配、核心規格欄位覆蓋率至少 90%、市價與價格類型能對應頁面且幣別／版本正確、所有缺值與衝突都明確提示、每筆資料可追溯到原頁與時間。未達標的品牌改走 CSV 或人工建檔，不擴大自動化範圍。

這個入口應放在 B 商品目錄的「新增商品」流程，處理商品基本資料、規格及官方公開市價，不含庫存；它也不同於現有 A 公司貨號 CSV 匯入。公司貨號是內部資料，仍需獨立的授權、存取權限及審核流程。正式實作前要先有後端、登入和來源網域核准清單。本次只完成可行性設計，沒有串接網站抓取。
